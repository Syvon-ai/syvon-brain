# Syvon Brain direction

The current organism remains the foundation. Read the [domain vocabulary](../CONTEXT.md) and [work contracts](WORK-CONTRACTS.md) for how intent, selected inputs, desired outcomes and Dream Mode fit it.

## Available

Workspace structure, brand DNA, capabilities and permissions, approvals, cards, revisions and signal collection remain intact. Additive v1 contracts now describe work scopes, revision-bound grants, outcome observations and Dream receipts. They include strict parsers, canonical scope serialization, optional path conventions and a runnable example.

These records do not execute work. No live Dream Mode integration or scheduler is shipped by this change.

## Next public anatomy work

- Exercise the contracts against real adapters and round-trip workspace exports, including approved snapshots and referenced evidence.
- Add migration guidance only when an existing record actually changes; current workspaces need none.
- Standardize portable source/evidence links and interoperability fixtures based on real consumers.
- Define recurrence contracts only after bounded finish is proven. A schedule cannot mint new authority.
- Keep outcomes, agent attempt reports, human approvals and learned guidance distinct.

## Syvon's private product work

Prove the existing-project loop: material, intention, correctable direction, first result, human correction, approved finish, progressed work. Build Dream orchestration on the actual execution and review paths, with enforced budgets, pause/revocation and meaningful idle results.

Context selection, retrieval, planning, prioritization, evaluation, refinement and premium skills remain private implementations. Studio and Surface consume the same Brain; this roadmap does not propose a public clone of their UI or a new separate Brain application.

## Intelligence principles

Keep evidence and provenance; distinguish unreadable state from empty state; apply corrections at the right scope; use approved source revisions; measure useful outcomes rather than output volume. Review cards, revisions, existing objectives and taste helpers must inform integration rather than being replaced by new parallel systems.

Open anatomy makes the workspace portable. The hosted operator earns its place through quality, reliability and useful progress.
